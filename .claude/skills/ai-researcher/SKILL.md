# AI-Researcher — исследование и наполнение базы

Скилл управляет витриной **AI-Researcher** через MCP-сервер `ai-researcher`
(инструменты: `list_bases`, `create_base`, `add_rows`, `query_records`,
`update_record`, `catalog_search`, `research_decompose`).

Если инструменты `ai-researcher` недоступны — сервер не подключён; скажи
пользователю подключить его по `mcp/README.md` и остановись.

## Когда что делать

**«Что есть в каталоге по X»** → `catalog_search { query: X, section?, limit }`.
Верни компании (name, verdict, section, url), кратко сгруппируй.

**«Исследуй тему X»** (разведка, без записи):
1. `research_decompose { prompt: X }` → подтемы.
2. По каждой значимой подтеме — `catalog_search` (ключевые слова подтемы).
3. Синтез: по каждой подтеме — что уже есть в каталоге (реальные компании) и
   где пробел («новая ниша»). Не выдумывай компании — только из `catalog_search`.

**«Собери/наполни базу по X»** (с записью):
1. Разведка как выше (decompose + catalog_search).
2. `list_bases` — проверь, нет ли уже такой базы (не дублируй).
3. `create_base { name, columns, rows }` — колонки осмысленные под тему
   (напр. Название/Вертикаль/Вердикт/Ссылка/Заметка), rows — из найденного в
   каталоге. Строки — объекты по label колонки.
4. Что не поместилось сразу — `add_rows`. Правки — `update_record`.
5. Отчитайся: id базы, сколько строк, ссылка `?base=<id>`.

## Правила

- **Только реальные данные.** Компании и факты бери из `catalog_search`, не
  сочиняй. Если по подтеме совпадений нет — так и напиши («новая ниша»).
- **Не дублируй базы** — сначала `list_bases`.
- **Встроенные базы** (market/ai/it/workforce) — только чтение; создавать и
  писать можно лишь в пользовательские.
- **Числа** передавай как есть — сервер приводит к числу для number-колонок.
- Перед созданием базы с большим числом строк покажи план (название, колонки,
  сколько строк) и дождись подтверждения.
