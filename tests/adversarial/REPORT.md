## Сломалось — по каждой дыре

### 1. Хранимая XSS через колонку типа url — критично

**Где.** Значение сохраняется без проверки схемы: `app/api/records/route.ts:205,213` (POST) и `:234,241` (PATCH). Рендер — `node_modules/@aivocado/mindsheet/MindSheet.tsx:1641`: анкор с href={String(value)} без нормализации.
**Шаги.** POST /api/records с data.ссылка = "javascript:fetch('/api/bases')" в базу с колонкой типа url, затем клик по ссылке в таблице.
**Реально.** Значение сохраняется как есть и попадает в href.
**Ожидалось.** Схема не из белого списка (http, https, mailto) — отказ или обезвреживание при записи.
**Серьёзность: критично.** Витрина за общей сессией; код выполняется на нашем origin от имени того, кто кликнул. Смягчение — строку может залить только вошедший сотрудник.

### 2. Чужой HTML на нашем домене без изоляции — критично

**Где.** `app/s/[id]/[[...path]]/route.ts:49-57` — заголовки только Content-Type, X-Content-Type-Options, Cache-Control. Ни Content-Security-Policy, ни sandbox.
**Шаги.** Залить сайт со скриптом, дёргающим /api/bin с confirm:true, и дать коллеге ссылку /s/<id>/index.html.
**Реально.** Скрипт исполняется на том же origin, что и витрина, с сессионными куками смотрящего.
**Ожидалось.** Отдельный origin либо жёсткий CSP (default-src 'none'; sandbox) на всей ветке /s/.
**Серьёзность: критично.** Тот, кто может залить сайт, действует за любого, кто его откроет. Тот же вектор работает через .svg (отдаётся как image/svg+xml).

### 3. Подмена id строки данными из запроса — критично

**Где.** `lib/datasource/customStore.ts:167` (объект собирается как id, режим, затем спред data — data.id перекрывает), `:173`, `:179` (Object.assign(row, patch)), `:367` (то же в Supabase-бэкенде).
**Шаги.** POST /api/records с data {name:"a", id:"дубль"} дважды — две строки с одинаковым id. Или PATCH с data {id:"угнанный"}.
**Реально.** id строки берётся из тела запроса; проверено обоими путями.
**Ожидалось.** id — только серверный; ключ id в data игнорируется или отвергается.
**Серьёзность: критично.** Последующие update_record / delete_rows / restore адресуются по этому же id и попадают не в ту запись.

### 4. Колонка с меткой ID перехватывает идентификатор строки — критично

**Где.** `app/api/mcp/route.ts:279-281` (ключ колонки выводится из метки, для «ID» он равен id) и `app/api/bases/route.ts:63,91`. Далее — п.3.
**Шаги.** Создать базу с колонкой «ID» и импортировать две строки с одинаковым внешним ID.
**Реально.** id обеих строк равен внешнему значению.
**Ожидалось.** Ключ id зарезервирован; колонка получает, например, id_.
**Серьёзность: критично.** В отличие от п.3 достигается обычным импортом таблицы, без злого умысла: «ID» есть в половине выгрузок из CRM.

### 5. Текст ошибки Supabase уходит в ответ — важно

**Где.** `app/api/records/route.ts:216`, `:245`; `app/api/bases/route.ts:124`; `app/api/columns/route.ts:58`; `app/api/records/reorder/route.ts:25`; `app/api/sites/route.ts:10`; `app/api/mcp/route.ts:663`.
**Реально.** В ответ уходит e.message дословно, включая имя отношения и класс ошибки БД.
**Ожидалось.** Наружу обобщённое сообщение, подробности в console.error — ровно как уже сделано в `app/api/records/route.ts:67-68` и `:119-120`.
**Серьёзность: важно.** Честная оговорка: ключ service_role в тестовое сообщение вставил я, чтобы показать механизм. Что Supabase кладёт ключ в текст ошибки — не доказано. Доказано другое: любой текст из Error.message уезжает пользователю дословно, включая чужую почту (отдельный падающий тест).

### 6. Цикл в дереве баз даёт вечную 500 на ветке — важно

**Где.** Проверка цикла: `app/api/bases/route.ts:148` — store.listBases(me), то есть только ВИДИМЫЕ проверяющему базы. Обход без защиты от повторов: `app/api/records/route.ts:89-95` и `:166-172` (walk без visited).
**Шаги.** (1) есть безвладельческая база A (видна всем); (2) Боб создаёт приватную B с parent = A (родитель не валидируется, п.7); (3) Алиса, не видящая B, двигает A под B — проверка не находит B среди потомков A и пропускает; (4) любой, кто видит и A, и B, открывает A.
**Реально.** Шаг 3 отвечает 200. Шаг 4 даёт RangeError: Maximum call stack size exceeded и 500 «Не удалось прочитать базу», навсегда.
**Ожидалось.** Цикл проверяется по ВСЕМ базам (как в MCP: wouldCreateCycle использует listAllBases), обход защищён множеством посещённых.
**Серьёзность: важно.** Отказ в обслуживании на ветке дерева, сам не рассасывается. GET /api/bases при том же цикле выживает (проверено).

### 7. parent не валидируется при создании и перемещении через MCP — важно

**Где.** `app/api/mcp/route.ts`, ветка create_base: parent берётся как есть и уходит в store.createBase. В move_base проверяется существование родителя, но НЕ доступ к нему.
**Реально.** База создаётся под чужим приватным или несуществующим узлом.
**Ожидалось.** Родитель обязан существовать и быть доступен вызывающему.
**Серьёзность: важно.** Ключевое звено сценария п.6 и способ подмешать свои строки в объединённый вид чужого дерева.

### 8. CSV-инъекция формулой — важно

**Где.** `lib/csv.ts:22-27` — csvField экранирует только по RFC 4180 и ничего не делает с ведущими знаками равно, плюс, минус и собакой.
**Шаги.** Значение вида =cmd|... или =IMPORTXML(...) в строке базы, затем «Скачать CSV» и открыть двойным кликом.
**Ожидалось.** Обезвреживание так, чтобы первым символом значения не был знак формулы. То же для меток колонок.
**Серьёзность: важно.** Классический путь к выполнению команды или эксфильтрации на машине получателя. Ведущие таб и CR не проверял — упомянуто как гипотеза.

### 9. Нет ни одного потолка на объём ввода — важно

**Где.** `app/api/records/route.ts` (POST/PATCH), `app/api/bases/route.ts` (POST и mapRows), `app/api/mcp/route.ts` (add_rows, create_base).
**Реально.** Проходят: ячейка 2 МБ, имя базы 100 000 символов, 10 000 строк одним запросом, объект глубиной 5000.
**Серьёзность: важно.** Один пользователь (или одна ошибшаяся модель через коннектор) забивает хранилище. Смягчение: на Vercel тело запроса ограничено примерно 4.5 МБ — количество строк этим не ограничено.

### 10. Загрузка файлов сайта в обход манифеста — важно

**Где.** `app/api/sites/[id]/files/route.ts:19-36`: проверяются только безопасность пути и размер одного файла. Ни соответствия манифесту, ни счётчика файлов, ни владельца.
**Реально.** POST на files существующего сайта с произвольным path — сколько угодно раз, 200.
**Серьёзность: важно.** MAX_FILES = 200 и общий объём обходятся полностью; попутно любой вошедший дописывает файлы в чужой сайт.

### 11. Суммарный объём загрузки не ограничен — важно

**Где.** `lib/sites/site.ts:103-127` — есть MAX_FILE_BYTES на файл и MAX_FILES на количество, суммы нет. 200 файлов ровно по 10 МБ проходят: 2 ГБ за одну загрузку.

### 12. Zip-slip не отсекается на распаковке — важно, эксплуатация не доказана

**Где.** `lib/sites/zip.ts:15-23` — unzipEntries фильтрует только мусор архиватора и записи-папки; запись с двумя точками в пути возвращается как обычный файл.
**Серьёзность.** Распаковка идёт в браузере, а серверный validateUpload такие пути отвергает (проверено, тест зелёный). Это отсутствующий второй рубеж, а не открытая дверь. Но unzipEntries экспортирован и используется на сервере в `app/api/sites/[id]/download/route.ts` — у следующего вызывающего защиты не будет.

### 13. Манифест с путями наружу тихо выправляется вместо отказа — важно

**Где.** `lib/sites/site.ts:74-84` stripCommonPrefix выполняется ДО isSafePath (`:106-120`). Набор путей, начинающихся с двух точек, целиком лежит «внутри» общей папки, она срезается, пути становятся безопасными.
**Серьёзность: важно (целостность, не выход за пределы).** Выхода из папки сайта нет — префикс именно срезается. Опасно тем, что сохранённая структура не соответствует загруженной.

### 14. Служебные поля записи принимаются из тела запроса — важно

**Где.** `app/api/records/route.ts:205` и `:234` — data берётся целиком, без сверки с колонками базы.
**Реально.** __mode с выдуманным значением и __pos: -999 сохраняются как есть.
**Серьёзность: важно.** __pos в Supabase-бэкенде задаёт порядок строк (`lib/datasource/customStore.ts:361-363`) — обычной правкой строки можно закрепить её наверху чужой таблицы. recordMode нормализует неизвестный режим при чтении, поэтому вкладка «Проверено» не врёт, но в хранилище остаётся мусор.
**Контраст:** через MCP то же самое невозможно — mapRow пропускает только ключи колонок. Дыра именно в REST-пути.

### 15. Префиксное сравнение в PUBLIC_PATHS — важно, латентно

**Где.** `middleware.ts:20` и `:70` — pathname.startsWith(p).
**Реально.** /api/mcp-evil и /loginXXX считаются публичными.
**Серьёзность: важно как ловушка, эксплуатация сегодня нулевая.** Таких роутов нет — Next отвечает 404 раньше. Но любой будущий /api/mcp-admin или /login-as окажется вне авторизации молча. Путь /.well-known/ записан со слэшем и потому защищён (проверено).

### 16. isAllowed пускает аккаунт без почты при пустом списке — важно, зависит от конфигурации

**Где.** `lib/supabase-auth.ts:14-21` — при пустом ALLOWED_EMAILS возвращается true до всякой проверки email; isAllowed(null) даёт true.
**Ожидалось.** Нет почты — нет доступа: вся модель делит данные по email, а owner === null означает «база, видимая всем».
**Серьёзность: важно, если в проекте Supabase включён анонимный или телефонный вход; иначе теоретично.** Включённые провайдеры проверить не мог — это состояние проекта, а не кода.

### 17. Границы пагинации query_records — важно

**Где.** `app/api/mcp/route.ts:463-464`, `:475`, `:481`.
**Реально.** offset -3 отдаёт хвост набора как «первую страницу»; нечисловой limit даёт NaN и пустой массив при hasMore: true; limit 1000000 отдаёт всю базу.
**Серьёзность: важно.** Вызывающая модель получает не ту страницу и не узнаёт об этом; при NaN — бесконечный цикл пагинации.

### 18. Потери и порча значений при записи через MCP — важно

**Где.** `app/api/mcp/route.ts:279-281`. Объект в значении превращается в строку object Object; нечисловая строка в числовой колонке — в NaN в хранилище.
**Серьёзность: важно.** NaN ломает сортировку и суммы; строка object Object — тихая потеря данных.

### 19. research_decompose без потолка длины — важно

**Где.** `app/api/mcp/route.ts:576-585` и `lib/research/decompose.ts:60-72`. Запрос в 1 МБ уходит в модель как есть.
**Серьёзность: важно.** Инструмент доступен любому валидному токену и расходует общий ANTHROPIC_API_KEY. Смягчение: без ключа отрабатывает эвристика (проверено).

### 20. data не того типа молча создаёт мусорную строку — косметика

**Где.** `app/api/records/route.ts:205` — проверка на объект пропускает массив; строка или число дают пустой объект и всё равно приводят к вставке.
Отдельно: пустой объект data я НЕ считаю дырой и тест на это убрал — UI отбрасывает пустые значения (`app/page.tsx:88-92`), добавление пустой строки может быть законным сценарием.

### 21. Переименование колонки в занятую метку — косметика

**Где.** `lib/datasource/customStore.ts:105-110` applyColumnPatch — уникальность проверяется только для ключа при создании, не для метки при правке. Ключи остаются разными, данные целы; ломается читаемость шапки CSV и фильтров.

### 22. Нулевой байт и перевод строки в пути файла сайта — косметика

**Где.** `lib/sites/site.ts:66-69` isSafePath — управляющих символов не проверяет. Из папки сайта такой путь не выводит; реакция Storage не проверена (до живого Supabase не ходил).

### 23. GET /api/mcp без токена перечисляет инструменты — косметика

**Где.** `app/api/mcp/route.ts:706`. Неавторизованный ответ содержит имена всех 18 инструментов, включая delete_base и empty_bin. Секретов там нет, почта не раскрывается (проверено).

### 24. Двоеточие внутри токена укорачивает его — косметика

**Где.** `lib/mcp/tokens.ts:17` — разбиение по ПЕРВОМУ двоеточию. Запись вида ab:cd:alice@example.com даёт рабочий токен ab.

### 25. Почта владельца в GET /api/bases — косметика, вероятно намеренно

**Где.** `app/api/bases/route.ts:20`, `:45`. Для доступной, но чужой (shared) базы уходит почта владельца. В коде это задокументировано как «кто создал базу» и, судя по всему, показывается в витрине сознательно. Тест оставлен падать как фиксация политики, а не как обвинение.

## Устояло — коротко

* **Мультиарендность.** 22 из 23 тестов зелёные. Чужую приватную базу нельзя прочитать, выгрузить в CSV, увидеть в списке или в корзине, дописать, отредактировать, удалить, переупорядочить, переименовать, переместить, восстановить, лишить колонки. canAccessBase применяется единообразно во всех восьми роутах.
* **Корзина.** Скоуп по доступу работает и в вебе, и в коннекторе (`lib/datasource/binAccess.ts` — одна реализация на двоих). «Очистить всё» не задевает чужие корзины.
* **Встроенные базы.** Все четыре read-only на всех путях записи: строки, колонки, порядок, имя, родитель, удаление.
* **Личные токены MCP.** Пустой, префикс, хвост, чужая схема, отозванный — отклоняются. Отзыв действует немедленно. Заголовок приоритетнее токена в строке запроса.
* **Обход middleware трюками с путём.** Две точки, кодированный слэш, двойное кодирование, регистр, matcher — закрыто. Fail-closed без Supabase на VERCEL работает.
* **isAllowed.** Поддомены, домен-хвост, второй знак собаки, кириллические омоглифы, усечения, мусор по краям — отвергаются; регистр не мешает своим.
* **Экранирование CSV по RFC 4180** и Content-Disposition (CRLF-инъекция невозможна, кириллица доезжает).
* **Path traversal в раздаче сайтов.** Две точки в любой позиции, обратный слэш, одиночная точка, пустой сегмент, ведущий слэш — 404.
* **Загрязнение прототипа.** Ключи __proto__ и constructor в data не трогают Object.prototype.
* **Идемпотентность.** Повторное удаление даёт 0, восстановление неудалённых даёт 0, выдуманные id дают 0, пустой список id — ошибка.
* **Устойчивость к мусору в MCP.** Неизвестный инструмент, другой регистр, отсутствующие или не те по типу аргументы — осмысленная ошибка. Битый JSON даёт -32700.
* **Целостность дерева в MCP.** wouldCreateCycle ловит self-loop, цикл из двух и из трёх звеньев; удаление базы с детьми не теряет детей; restore встроенной базы отклоняется.
* **research_decompose без ключа** отвечает эвристикой, а не падает.
* **Обобщённость ошибок на пути чтения** GET /api/records. Стек вызовов не попадает в ответ нигде.

## Не покрыто тестом

1. **RLS в Supabase.** `supabase/schema.sql` не содержит ни одного enable row level security для bases, base_records, sites; таблицы favorites в файле нет вовсе. Сервер ходит под service_role и RLS обходит по определению — ВСЯ мультиарендность держится исключительно на прикладном коде. Единичная ошибка в одном роуте равна полному доступу ко всем данным, второго рубежа нет. Юнит-тестом не воспроизводится: нужна живая БД и запрос под anon-ключом.
2. **Timing-safe сравнение токенов.** `lib/mcp/tokens.ts:29` — обычное строгое равенство. Тест на тайминг в vitest на Windows даст шум, а не сигнал; декоративный тест писать не стал.
3. **Токен в строке запроса.** `app/api/mcp/route.ts:27` — задокументированный компромисс. Утечка идёт в логи прокси, историю браузера и Referer. Тест зафиксировал, что механизм работает и что заголовок приоритетнее; сам компромисс тестом не оценивается.
4. **Zip-бомба.** unzipSync распаковывает в память целиком. Собрать настоящую бомбу в тесте — гигабайты в CI. Гипотеза: архив с высокой степенью сжатия положит функцию по памяти до всяких проверок размера, потому что validateUpload работает уже с распакованными размерами.
5. **Гонки.** Два одновременных reorder, одновременные add_rows и delete_rows. In-memory хранилище однопоточное, а Supabase-бэкенд делает read-modify-write без транзакции (`lib/datasource/customStore.ts:370-392` и `:428-441`) — последний записавший выигрывает, часть правок теряется. Честно смоделировать можно только против живой БД.
6. **Промпт-инъекция в research_decompose.** Пользовательский текст подставляется в сообщение модели (`lib/research/decompose.ts:69`). Результат используется только как список подтем, parseList берёт максимум 12 строк из JSON-массива. Проверить содержательно значит проверить поведение модели.
7. **CSP/sandbox на живом Vercel.** Заголовки могли бы добавляться на уровне платформы. Проверил только то, что отдаёт роут; в `next.config.js` заголовков нет, живой прод не трогал по условию задачи.
8. **Реальное поведение Supabase Storage** на ключах с нулевым байтом (п.22) и на кириллических id сайтов.
9. **UI-рендер.** Все атаки проверены на уровне API. Единственный dangerouslySetInnerHTML (`app/layout.tsx:22`) — статическая строка темы. React экранирует текст; ссылки исключение, вынесено в дыру номер 1.
