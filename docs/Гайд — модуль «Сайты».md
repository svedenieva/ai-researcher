# Сайты — хранилище готовых страниц

**Кому:** команде AiVocado Soft
**Зачем:** складывать статические сайты, собранные с ИИ, в одно место — чтобы их можно было открыть по ссылке, скачать обратно и найти по названию, клиенту или тегу.

Раздел живёт по адресу **/sites**, ссылка есть в шапке каталога.

---

## 1. Разовая настройка

Делается один раз, руками, в дашборде Supabase. Без этих двух шагов раздел покажет понятную ошибку, а не белый экран.

### Шаг 1. Завести бакет

Supabase → **Storage** → **New bucket**:

- имя — `sites` (ровно так, строчными);
- **Public bucket — выключить.** Бакет приватный: файлы отдаёт сервер приложения, а он уже проверил, что человек вошёл и есть в списке доступа. Публичный бакет открыл бы все сайты всему интернету по прямой ссылке.

### Шаг 2. Прогнать SQL

Supabase → **SQL Editor** → вставить и **Run**:

```sql
create table if not exists sites (
  id          text primary key,          -- слаг из названия, при совпадении суффикс -2
  name        text not null,
  client      text,
  tags        text[] not null default '{}',
  note        text,
  entry       text not null default 'index.html',
  file_count  int  not null default 0,
  size_bytes  bigint not null default 0,
  owner       text,                      -- почта того, кто залил
  created_at  timestamptz not null default now()
);
```

Тот же SQL лежит в репозитории — `supabase/schema.sql`.

### Шаг 3. Проверить переменные

В `.env.local` (локально) и в переменных проекта на Vercel уже должны быть:

| Переменная | Значение |
|---|---|
| `DATA_SOURCE` | `supabase` |
| `SUPABASE_URL` | адрес проекта |
| `SUPABASE_SERVICE_KEY` | ключ вида `sb_secret_…` |

> ⚠️ `SUPABASE_SERVICE_KEY` — именно **`sb_secret_…`**, а не длинный `eyJ…`. Старый JWT даёт ошибки «Invalid API key» и «JWT issued at future».

## 2. Как залить сайт

На странице **/sites** — кнопка загрузки. Принимает два вида:

- **папку целиком** — выбрать директорию с сайтом; структура вложенных папок сохраняется как есть;
- **`.zip`** — архив распаковывается прямо в браузере.

Если внутри архива всё лежит в одной общей папке (`мой-сайт/index.html`), эта папка срезается: в хранилище попадёт `index.html`, а не `мой-сайт/index.html`. Так ссылки внутри сайта не ломаются.

### Что не примет

| Правило | Почему |
|---|---|
| файл больше **10 МБ** | это витрина статики, а не файлопомойка |
| больше **200 файлов** | столько же |
| нет `index.html` в корне | нечего показывать. Если HTML-файл ровно один и лежит глубже — он станет стартовой страницей |

Файлы уходят **по одному**, с прогрессом. Это не медлительность, а обход ограничения: serverless-запрос на Vercel не принимает тело больше ~4,5 МБ, поэтому одной пачкой сайт не отправить.

Заполнить при загрузке можно **название**, **клиента**, **теги** и **заметку**. Обязательное — только название.

## 3. Что дальше можно делать

| Действие | Как |
|---|---|
| **Открыть** | кнопка в строке — сайт открывается живым, со своими стилями и картинками |
| **Скачать** | кнопка в строке — собирает `.zip` со всеми файлами обратно |
| **Найти** | поиск сверху ищет по названию, клиенту и заметке; рядом фильтр по тегу |
| **Отсортировать** | по дате или по названию |
| **Удалить** | кнопка в строке, с подтверждением |

Удаление **необратимо** — сносит и файлы, и запись. Версий и корзины нет, восстановить будет неоткуда.

---

## 4. Кто что видит

Все сайты видны всем, кто вошёл и есть в списке доступа. Это общий реестр компании, а не личное пространство: у баз знаний доступ разделён по владельцам, у сайтов — нет, так задумано. Поле «залил» показывает автора, но ничего не ограничивает.

Ссылка на сайт **не публичная**: человек без входа увидит страницу логина. Показать сайт клиенту по такой ссылке не получится — для этого нужен обычный хостинг.

---

## 5. Ограничения, о которых лучше знать заранее

**Пути к файлам — только относительные.** Сайт, который тянет стили как `/style.css` (со слэша в начале), не отрисуется: слэш ведёт в корень домена, а сайт лежит по своему адресу. Работает `style.css`, `./style.css`, `assets/style.css`.

Если сайт собирает ИИ — так и просите: **пути относительные, без ведущего слэша**. Это единственное требование к вёрстке.

**Чего в разделе нет и не планируется:**

- истории версий — новая заливка не хранит предыдущую;
- редактирования файлов в браузере;
- публичных ссылок и своих доменов.

---

## 6. Если не работает

| Симптом | Что делать |
|---|---|
| «Хранилище не настроено» | не создан бакет `sites` — шаг 1 |
| Ошибка про таблицу `sites` | не прогнан SQL — шаг 2 |
| Сайт открылся, но без стилей и картинок | в HTML корневые пути `/style.css` — заменить на относительные |
| «Нет `index.html` в корне» | стартовая страница названа иначе или лежит глубже — переименовать в `index.html` |
| Загрузка встала на середине | сеть отвалилась; удалить запись и залить заново |
| Файл не принят | больше 10 МБ — сжать картинку или видео |
