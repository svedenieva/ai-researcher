Сайты — хранилище готовых страниц

Раздел, куда складываются статические сайты, собранные с ИИ: залить папкой или архивом, открыть живым по ссылке, скачать обратно и найти по названию, клиенту или тегу.

Раздел /sites — ссылка в шапке каталога
01 Разовая настройка бакет + SQL, один раз
Шаг 1. Завести бакет
Supabase → Storage → New bucket. Имя — sites, ровно так, строчными.
Public bucket — выключить. Бакет приватный: файлы отдаёт сервер приложения, а он уже проверил, что человек вошёл и есть в списке доступа. Публичный бакет открыл бы все сайты всему интернету по прямой ссылке.
Шаг 2. Прогнать SQL
Supabase → SQL Editor → вставить и Run. Тот же запрос лежит в репозитории, в supabase/schema.sql.
create table if not exists sites (
  id          text primary key,          -- слаг из названия, при совпадении суффикс -2
  name        text not null,
  client      text,
  tags        text[] not null default '{}',
  note        text,
  entry       text not null default 'index.html',
  file_count  int  not null default 0,
  size_bytes  bigint not null default 0,
  owner       text,                      -- почта того, кто залил
  created_at  timestamptz not null default now()
);
Шаг 3. Проверить переменные
В .env.local и в переменных проекта на Vercel уже должны быть:
ПеременнаяЗначение
DATA_SOURCEsupabase
SUPABASE_URLадрес проекта
SUPABASE_SERVICE_KEYключ вида sb_secret_…

Ключ — именно sb_secret_…, а не длинный eyJ…. Старый JWT даёт ошибки «Invalid API key» и «JWT issued at future».

02 Как залить сайт папкой или архивом
  • Папкой целиком — выбрать директорию с сайтом, структура вложенных папок сохраняется как есть.
  • Архивом .zip — распаковывается прямо в браузере.
Лишняя обёртка срезается сама
Если внутри архива всё лежит в одной общей папке (мой-сайт/index.html), эта папка срезается: в хранилище попадёт index.html. Так ссылки внутри сайта не ломаются.
Что не приметПочему
файл больше 10 МБэто витрина статики, а не файлопомойка
больше 200 файловстолько же
нет index.html в корненечего показывать. Если HTML-файл ровно один и лежит глубже — он станет стартовой страницей
Почему грузится по одному файлу
Это не медлительность, а обход ограничения: serverless-запрос на Vercel не принимает тело больше ~4,5 МБ, поэтому одной пачкой сайт не отправить. Прогресс виден на экране.
Что заполнить
Название — обязательно. Клиент, теги и заметка — по желанию, по ним потом ищется.

04 Кто что видит общий реестр, не личное пространство
Все сайты видны всем, кто вошёл
Это общий реестр компании. У баз знаний доступ разделён по владельцам, у сайтов — нет, так задумано. Поле «залил» показывает автора, но ничего не ограничивает.
Ссылка на сайт не публичная
Человек без входа увидит страницу логина. Показать сайт клиенту такой ссылкой не получится — для этого нужен обычный хостинг.
05 Ограничения пути только относительные
Пути к файлам — только относительные
Сайт, который тянет стили как /style.css (со слэша в начале), не отрисуется: слэш ведёт в корень домена, а сайт лежит по своему адресу.
Работает: style.css, ./style.css, assets/style.css.

Если сайт собирает ИИ — так и просите: пути относительные, без ведущего слэша. Это единственное требование к вёрстке.

Чего в разделе нет и не планируется
Истории версий — новая заливка не хранит предыдущую. Редактирования файлов в браузере. Публичных ссылок и своих доменов.
