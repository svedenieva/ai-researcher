## Сопоставление с уровнями модели из ТЗ

ТЗ описывает четыре уровня (база исследований → процесс → база данных → база знаний)
и четыре ветки базы знаний (Software / AI Sphere / Workflows / Products & Competitors,
зафиксированы 28.07). **Живая структура отличается** — это надо согласовать с куратором,
макеты собираются по реальной схеме, а не по идеализированной:

- Уровень «база знаний» реально существует как `ai-baza-znaniy` с детьми
  `Элементы` / `Автоматизация` / `Разработка` — это НЕ ветки Software/AI Sphere/Workflows/Products.
- Наполненные базы, пригодные для макетов «на реальных данных»: `инструменты` (35),
  `табличные-системы` (15), `второй-мозг` (1, но полная mindbook-схема).
- `исследования` пуста (0), `ai-issledovanie` объявлена одной колонкой — уровень
  «процесс исследования» в данных пока не развёрнут.

## Схемы наполненных баз (для artboards)

### `инструменты` — 35 записей (эталон таблицы базы данных/знаний)
| key | type | filterable |
|---|---|---|
| название | text | — |
| категория | select | ✓ |
| подпроцесс | select | ✓ |
| возможности | long-text | — |
| как_пользоваться | long-text | — |
| ссылка_на_гайд | url | — |
| режим_записи | select | ✓ |
| первоисточник | url | — |
| гайд | long-text | — |

- Реальные значения `категория`: Автоматизация, Производство контента, Разработка ПО.
- `режим_записи`: Черновик / Эталон (ФТ-10 — статусы; тумблер черновик/эталон в тулбаре).
- Записи несут `__mode` (режим записи), `__updated` (дата), `__fmt` (формат ячейки:
  align/color/italic) — это входные данные для табличного вида (ФТ-06) и плотности (ФТ-15).

### `табличные-системы` — 15 записей (референс для design-системы Mindsheet)
Колонки: название, вендор, категория(select), модель_данных(select), типизация(select),
уровни_сортировки, уровни_группировки, лимит_строк, ссылка(url), заметка(long-text).
Содержит исследование самих табличных систем (Google Sheets, Excel, …) — прямой источник
требований к сортировке/группировке/переполнению ячейки для Mindsheet.

### `второй-мозг-на-ai-тест-24812` — mindbook-схема
Колонки: название, **стадия** (select-badge), описание, инструкции, чек_лист, источники,
цитата, сайт(url), проверка×3(text).
- `стадия` — бейдж со **строгим порядком** `Изучаю → Тестирую → Внедрено` и цветами
  `blue / amber / green` (`badgeVariant`). Это готовая спецификация статус-бейджа (ФТ-10).

## Статусы и бейджи (ФТ-10) — инвентарь
- Режим записи: **Черновик / Эталон** (тумблер над таблицей).
- Стадия внедрения: **Изучаю (blue) / Тестирую (amber) / Внедрено (green)**.
- Смена статуса — кликом по бейджу (правило Mindsheet).

## Реестр доверенных источников (ФТ-12)
`list_trusted_sources(topic)` отдаёт ветбанные источники с полями: name, **type**
(expert / platform), url, topics[], note. Пример по «AI инструменты автоматизации»:
Andrej Karpathy (expert), Sam Altman (expert), Hacker News (platform), arXiv cs.AI (platform).
→ отдельный раздел интерфейса: дерево по type, карточки с note и topics.

## Что из этого следует для макетов
1. Табличный вид (ФТ-06) строится на схеме `инструменты`: колонки разных типов,
   3 filterable-поля (категория, подпроцесс, режим_записи) → двойная фильтрация (ФТ-08).
2. Плотность (ФТ-15): строка = набор коротких полей + long-text, раскрываемый вбок
   (не растягивая строку). 20+ строк на 900px — цель проверяется на реальных 35 записях.
3. Статус-бейджи (ФТ-10) уже специфицированы данными (`badgeVariant`).
4. Дерево баз (ФТ-07) — реальное `parent`-дерево выше, цвет ветки наследуется от родителя.
5. Языки (ФТ-14): данные преимущественно RU, заметки в trusted_sources — UA. Проверка
   длины подписей на UA (по умолчанию) обязательна.
