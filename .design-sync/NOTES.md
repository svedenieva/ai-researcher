# design-sync — заметки по этому репозиторию

Канал 1 моста «код → Claude Design». Парный канал — `/design-pull`
(`.claude/skills/design-pull/`). Проект: `AI Researcher`,
`https://claude.ai/design/p/fc6d3584-8574-4f11-ab0e-f2620069d87a`.

## Как это собирается

- **Репозиторий вне штатного конверта конвертера.** Это Next.js-приложение, а не
  библиотека: нет `dist/`, нет Storybook, нет библиотечного энтрипоинта. Поэтому
  энтрипоинт написан руками — `.design-sync/entry.tsx`, и флаг `--entry` обязателен
  в каждом прогоне. Без него конвертер уйдёт в synth-режим и потянет `app/**` целиком,
  включая роут-файлы с `next/link` и `next/navigation` — сборка упадёт.

- **Команда сборки** (обе стадии отдельно, коды возврата проверять по одной):
  ```bash
  node .ds-sync/package-build.mjs --config .design-sync/config.json \
    --node-modules ./node_modules --entry ./.design-sync/entry.tsx --out ./ds-bundle
  node .ds-sync/package-validate.mjs ./ds-bundle
  ```
  Пере-синк — через драйвер `resync.mjs` с теми же флагами плюс `--remote <якорь>`.

- **Состав фиксирован `componentSrcMap`.** Автообнаружение здесь ничего не находит
  (нет `.d.ts`-экспортов), поэтому список из 18 компонентов задан явно. Новый
  компонент в дизайн-проекте появится только после записи в `componentSrcMap` **и**
  экспорта из `entry.tsx` — двух мест, не одного.

- **Страницы не синкаются намеренно.** 13 файлов `app/**/page.tsx` и
  `app/topic/**` тянут `next/link` / `next/navigation` / `next/dynamic` и вне
  Next-рантайма смысла не имеют.

- **`guidelinesGlob: []` намеренно.** По умолчанию конвертер утаскивает `docs/*.md`,
  а там лежит онбординг самого моста — дизайн-агенту это шум, и хуже: текст
  адресован Claude Code и читается как инструкции.

## Провайдеры и превью

- `cfg.provider` = `DsProvider` (`.design-sync/ds-provider.tsx`) — повторяет
  `app/layout.tsx`: `LangProvider` + `UiProvider`. Без него компоненты монтируются,
  но падают на украинскую локаль по умолчанию и молча теряют тосты.

- **Панели открываются программно.** `StagesPanel`, `ConfirmationsPanel`,
  `SavedViews`, `BaseAccess`, `BaseAiActions`, `FilterConditions` держат `open` во
  внутреннем состоянии, поэтому статический рендер показал бы только закрытый
  триггер. `AutoOpen` из `.design-sync/fixtures.tsx` кликает по триггеру после
  монтирования. `Shortcuts` триггера не рисует вовсе (пока закрыт — возвращает
  `null`) и слушает `?` на `window` — для него `PressKey`.

- **Панелям нужна сцена.** Все выпадающие панели привязаны `right: 0` и имеют ширину
  284–420 px. Триггер, стоящий в нуле по X, роняет панель за левый край карточки.
  `PanelStage` даёт правое выравнивание и габариты; в `cfg.overrides` для каждой
  такой панели прописан `cardMode: "single"` с вьюпортом под размер сцены.

- **Группа `IconGallery` задаётся именем папки.** Файл лежит в
  `.design-sync/icons/`, а не в корне `.design-sync/`, потому что группа,
  выведенная из пути, побеждает `category` из доки — фронтматер применяется только
  когда путь дал `general`. Переложите файл — поменяется группа.

## Известные предупреждения рендера

Пере-синк сверяет предупреждения с этим списком; всё, чего здесь нет, — новое,
и это надо смотреть.

- `[FONT_MISSING] "Cascadia Code"` — **доброкачественное**. Это системный фолбэк в
  стеке `--font-mono` (`'JetBrains Mono', ui-monospace, 'SF Mono', 'Cascadia Code',
  Menlo, Consolas, monospace`), а не брендовая гарнитура. Возить её не нужно и нечего.

## Шрифты

`.design-sync/fonts/` — 16 woff2 (DM Sans 400/500/600/700, JetBrains Mono 400/500)
плюс `fonts.css`. Продакшен грузит их `<link>`-ом из Google Fonts в `app/layout.tsx`,
но у отрисованного дизайна такого `<link>` нет, поэтому гарнитуры едут с бандлом.

- Подмножества: `latin`, `latin-ext`, `cyrillic`, `cyrillic-ext`; `greek` и
  `vietnamese` отброшены сознательно.
- **У DM Sans кириллицы нет вообще** — этого начертания не существует в апстриме.
  Кириллический текст падает на системный гротеск и здесь, и в продакшене; это
  свойство продукта, а не потеря при переносе.
- Перегенерировать: забрать
  `https://fonts.googleapis.com/css2?family=DM+Sans:wght@400;500;600;700&family=JetBrains+Mono:wght@400;500&display=swap`
  с браузерным User-Agent (иначе Google отдаст ttf вместо woff2), отфильтровать блоки
  по комментарию подмножества, скачать `url()` и переписать их на `./<Имя>-<вес>-<подмножество>.woff2`.

## Чем рискует следующий синк

- **Фикстуры повторяют доменную модель руками.** `.design-sync/fixtures.tsx`
  воспроизводит форму `ColumnDef` / `CatalogRecord` и ключи, которые ищут панели
  (колонка со стадией по `/стад|stage|этап/`, колонки-ссылки по
  `/источник|source|url|ссылк|посилан|link/`, `defaultGroup` для воронки
  `BaseSummary`). Поменяется эвристика в `lib/knowledge-stages.ts`,
  `lib/source-counters.ts` или `lib/research/confirmations.ts` — карточки тихо
  опустеют, не сломавшись. Смотреть контактные листы, а не только коды возврата.
- **Приём с программным открытием панелей завязан на разметку.** Если триггер
  перестанет быть первой `<button>` внутри компонента, `AutoOpen` промахнётся, и
  карточка снова покажет закрытое состояние — тоже молча.
- **Шрифты пришиты по URL Google Fonts.** Апстрим меняет версии подмножеств;
  файлы в `fonts/` — снимок на момент синка, автоматически они не обновляются.
- **Что проверено не машиной, а глазами:** осмысленность содержимого карточек.
  Рендер-чек ловит пустоту и обрезку, но не то, что данные перестали быть
  правдоподобными.
- **Чего в превью нет:** состояний, которые статикой не снять — hover, drag,
  фокус-кольца, живые ответы ИИ-действий и результаты поиска (они ходят в API).

## Баг парсера tsconfig в скилле design-sync (белый экран) — ОБЯЗАТЕЛЬНО

- **Симптом:** карточка FullSite (или любой компонент, тянущий `@/…` алиасы)
  рендерит белый экран; в бандл попадает НАСТОЯЩИЙ `next/navigation`, и
  `useRouter()` вне Next бросает исключение.
- **Причина:** парсер tsconfig в скилле вырезает блочные комментарии регуляркой
  `/\*…\*/` и принимает `"@/*": ["./*"]` за начало комментария — файл съедается
  до ближайшего `*/`, JSON молча рушится, плагин путей возвращает null, алиасы
  (в т.ч. подмены `next/*` на шимы) игнорируются.
- **Фикс (в этом репо уже сделан):** используем отдельный `tsconfig.dssync.json`
  (в корне репо, `config.tsconfig` указывает на него), где в `paths` НЕТ
  последовательности `/*`. Вместо `"@/*": ["./*"]` — `"@/lib*": ["lib*"]`,
  `"@/app*": ["app*"]` (звёздочка сразу после слова, без `/` перед ней). Никаких
  `include`-глобов с `**/*` — там тоже `/*`. Настоящий `tsconfig.json` не трогаем.
- **Проверка:** grep по бандлу — настоящего `next` 0, шим 1; JSON парсится; экран
  не белый. Следующий синк на эти грабли не наступит, пока `config.tsconfig`
  указывает на `tsconfig.dssync.json`.

## FullSite — весь сайт одной редактируемой карточкой

- **Что это:** `app/page.tsx` (`Home`) целиком как одна карточка (компоненты —
  отдельно, как раньше). Даёт «правь сайт целиком», а не только кирпичики.
- **Как собрано:** `config.componentSrcMap.FullSite = app/page.tsx`; экспорт в
  `entry.tsx`; превью `previews/FullSite.tsx`; override `{cardMode: single,
  viewport: 1440x900}`.
- **Шимы (в `.design-sync/shims/`, подключены через `tsconfig.dssync.json`
  paths):** `next-navigation` (инертный useRouter — убирает белый экран),
  `next-link` (обычный `<a>`), `api` (apiJson отдаёт `CATALOG_COLUMNS` + реальные
  строки каталога на `/api/records`, `{bases:[]}`/`{favorites:[]}` на прочее;
  apiSend — no-op).
- **Если FullSite не собирается при билде (его надо гонять в залогиненной
  сессии):** почти всегда это ещё один импорт из `app/page.tsx`, которого нет в
  шимах/алиасах — посмотреть ошибку esbuild, добавить недостающий шим по образцу
  и пересобрать. `@aivocado/mindsheet` — реальный пакет, бандлится из
  node_modules.
